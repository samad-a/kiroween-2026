Structured from the Devpost overview and Official Rules (full text: [devpost-rules-full.md](devpost-rules-full.md), source: https://kiroween.devpost.com/rules). If this summary and the Official Rules disagree, the Official Rules win.

## Eligibility
- Age of majority where you live; teams of up to 3 (or organisations).
- Excluded regions include Quebec, Argentina, Australia, Brazil, Italy, Philippines, Russia, UAE and OFAC-sanctioned countries.
- **New projects only**: built during the Submission Period. Frameworks, libraries and starter templates are fine, but any other pre-existing code or work must be disclosed.
- Must not be developed with financial or preferential support from AWS or Devpost.

## Categories (pick one)
- **Resurrection**: bring a dead technology back to life, reimagined with today's innovations or solving tomorrow's problems. ← Club Kiro
- Frankenstein, Skeleton Crew (needs 2 apps in 2 folders), Costume Contest.
- More than one submission is allowed only if each is substantially different.

## Project requirements
- A working software application built using Kiro (IDE, CLI, Web and/or Crew). **Insufficient use of Kiro = disqualification.**
- Must install and **run consistently** on its intended platform, and work as shown in the video and description.
- Third-party SDKs, APIs and data must be used within their terms.

## Submission checklist
- [ ] Category and bonus prizes selected
- [ ] **Public GitHub repo** (not GitLab/Bitbucket) with all source, assets and instructions needed to run it
- [ ] **Open-source licence file**, detected and shown in the repo's About section
- [ ] **`/.kiro` at the repo root**, never in `.gitignore` (doing so can disqualify)
- [ ] **URL to the working app**. Free and unrestricted for judges until **Jan 29, 2027**. Any login details go in the private Devpost field
- [ ] Text description of features and functionality
- [ ] **Demo video**: under 3 minutes (judges may stop at 3:00), shows it working on the intended device, **public on YouTube**, no third-party trademarks, copyrighted music or other copyrighted material without permission
- [ ] **Kiro write-up** (see below)
- [ ] English, or English translations of all materials
- [ ] Bonus-prize extras (see below)

### Kiro write-up: the eight prompts judges list
1. Kiro IDE, CLI, Web, Crew: how did they differ, if you tried several?
2. Custom agents: which ones, in which Kiro app, and what impact?
3. Agent hooks: which workflows did you automate, and how did they help?
4. Spec-driven development: how were specs structured, how did it help, and how did it compare with vibe coding?
5. Steering docs: how did steering improve responses, and which strategy mattered most?
6. MCP: what did extending Kiro enable that would otherwise be hard or impossible?
7. Property-based testing: did PBT catch issues unit tests would miss, and for which requirements?
8. Kiro powers: which powers, and what tooling or integrations did they bring?

## Judging
- **Stage one (pass/fail)**: reasonably fits the theme and reasonably uses the required tools.
- **Stage two**: five criteria, 10 points each, equally weighted:
  - **Potential Impact**: a real problem for a real audience, addressed by what's demonstrated. Useful, intuitive, accessible. Would someone use it?
  - **Technological Implementation**: how thoroughly and skilfully Kiro is used, with a thoughtful AI-development strategy, variety of tools, deep understanding and experimentation.
  - **Design**: a complete, coherent product, not a tech proof of concept. Intuitive, polished, intentional.
  - **Innovation/Idea**: creative and novel, different from existing concepts, with unusual technologies or public resources combined in new ways.
  - **Presentation**: the video shows it working end to end; the pitch says what problem, for whom and why it matters; easy to follow, creative and memorable.
- Judging may use expert panels, peer review, **automated AI-driven analysis**, or a mix.
- **Judges don't have to test the app.** They may judge on the description, images and video alone.
- Ties are re-scored from scratch on a 20-point scale per criterion.

## IP and changes
- Must be your original work, solely owned, and must not infringe anyone's IP, including **trademark** and **privacy** rights.
- Sponsor or Devpost IP (logos, trademarks and so on) may only be used as the rules allow.
- Open-source dependencies are fine if their licences are followed.
- **After the deadline the submission can't be changed**, except material that infringes rights or exposes personal data. You can keep updating the Devpost portfolio page.
- AWS and Devpost may use your name, likeness and submission in promotion.
